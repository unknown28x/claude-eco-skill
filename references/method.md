# Working method

A poorly scoped task is paid for twice. Scoping is a saving, not a formality.

## Before a large task
1. Ask **all** necessary questions at once, then proceed without interrupting.
2. Summarize in 3 points: the task / the guardrails / what the finished result looks like.
3. Fix a yes/no verification check.
   Example: "the page renders without errors on mobile, with a screenshot as proof".

## During
- If the user gives an example, follow its form: an example beats a description.
- If an approach fails twice, stop and change hypothesis instead of retrying in a loop.

## Before saying "it's done"
Prove the check fixed at the start. State explicitly what is not done or not verified.

## At session end
- Save to memory what will still be useful: preferences, corrections, decisions.
  One memory = one fact. Not what the code or git already records.
- If the work continues later: write the handoff note (`session.md`).
